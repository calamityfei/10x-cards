# PostgreSQL Database Schema - 10xCards

This document outlines the database schema for the 10xCards MVP, designed for Supabase (PostgreSQL).

## 1. Tables and Schema

### User Management (Handled by Supabase Auth)

User data is managed in Supabase's private `auth.users` table. All tables below reference this table's `id` (UUID) column.

---

### `public.flashcards`

Stores the individual flashcards created by users. Trigger: Automatically update the `updated_at` column on record updates.

| Column          | Type           | Constraints & Notes                                       |
| :-------------- | :------------- | :-------------------------------------------------------- |
| `id`            | `bigserial`    | `GENERATED BY DEFAULT AS IDENTITY`, `PRIMARY KEY`         |
| `user_id`       | `uuid`         | `NOT NULL`, `REFERENCES auth.users(id) ON DELETE CASCADE` |
| `generation_id` | `bigint`       | `REFERENCES generations(id) ON DELETE SET NULL`           |
| `front`         | `varchar(200)` | `NOT NULL`                                                |
| `back`          | `varchar(500)` | `NOT NULL`                                                |
| `source`        | `card_source`  | `NOT NULL` (See `card_source` ENUM type below)            |
| `created_at`    | `timestamptz`  | `NOT NULL`, `DEFAULT now()`                               |
| `updated_at`    | `timestamptz`  | `NOT NULL`, `DEFAULT now()`                               |

---

### `public.generations`

A log table to track the summary of each AI generation event for metrics.

| Column                    | Type           | Constraints & Notes                                                                |
| :------------------------ | :------------- | :--------------------------------------------------------------------------------- |
| `id`                      | `bigserial`    | `PRIMARY KEY`                                                                      |
| `user_id`                 | `uuid`         | `NOT NULL`, `REFERENCES auth.users(id) ON DELETE CASCADE`                          |
| `model`                   | `varchar(100)` | `NULL` (Model identifier of LLM used)                                              |
| `generation_duration`     | `integer`      | `NULL` (Time in milliseconds)<br>`CHECK (generation_duration > 0)`                 |
| `source_text_hash`        | `char(64)`     | `NULL` (SHA-256 hash of the source text)                                           |
| `source_text_length`      | `integer`      | `NOT NULL`<br>`CHECK (source_text_length >= 1000 AND source_text_length <= 10000)` |
| `generated_count`         | `integer`      | `NOT NULL`, `DEFAULT 0`, `CHECK (generated_count >= 0)`                            |
| `accepted_unedited_count` | `integer`      | `NOT NULL`, `DEFAULT 0`, `CHECK (accepted_unedited_count >= 0)`                    |
| `accepted_edited_count`   | `integer`      | `NOT NULL`, `DEFAULT 0`, `CHECK (accepted_edited_count >= 0)`                      |
| `deleted_count`           | `integer`      | `NOT NULL`, `DEFAULT 0`, `CHECK (deleted_count >= 0)`                              |
| `created_at`              | `timestamptz`  | `NOT NULL`, `DEFAULT now()`                                                        |

### Custom Types (ENUMs)

**`public.card_source`**
A custom ENUM type to satisfy PRD Metric 6.2 (AI Feature Adoption).

```sql
CREATE TYPE public.card_source AS ENUM (
  'ai_full',   -- Generated by AI and accepted without edits
  'ai_edited', -- Generated by AI and edited before saving
  'manual'     -- Created using the manual add flow
);
```

## 2. Relationships

### auth.users to flashcards: One-to-Many

- A single user can own many flashcards.
- `flashcards.user_id` is the foreign key.
- The relationship uses `ON DELETE CASCADE` to automatically delete a user's flashcards when their account is deleted (US-005).

### auth.users to generations: One-to-Many

- A single user can have many generation log entries.
- `generations.user_id` is the foreign key.
- The relationship uses `ON DELETE CASCADE`.

## 3. Indexes

Indexes are created to speed up common queries and enforce Row-Level Security.

### On flashcards table:

```sql
CREATE INDEX ON public.flashcards (user_id);
```

Reason: Critical for RLS policies and for fetching all flashcards for a specific user (US-012).

### On generations table:

```sql
CREATE INDEX ON public.generations (user_id);
```

Reason: Critical for RLS policies and for any future metric analysis grouped by user.

Note on Search: Per decision #10, no indexes are created for the front or back columns to support search (US-013), as the LIKE '%query%' search will not use a standard B-tree index. This is an accepted performance trade-off for the MVP.

## 4. PostgreSQL Policies (Row-Level Security)

RLS must be enabled on both tables to ensure users can only access their own data.

### Flashcards Policies:

```sql
-- 1. Enable RLS on the table
ALTER TABLE public.flashcards ENABLE ROW LEVEL SECURITY;

-- 2. Policy for SELECT
-- Users can read their own flashcards.
CREATE POLICY "Enable read access for user's own flashcards"
ON public.flashcards
FOR SELECT USING (
  auth.uid() = user_id
);

-- 3. Policy for INSERT
-- Users can create new flashcards for themselves.
CREATE POLICY "Enable insert for own flashcards"
ON public.flashcards
FOR INSERT WITH CHECK (
  auth.uid() = user_id
);

-- 4. Policy for UPDATE
-- Users can update their own flashcards.
CREATE POLICY "Enable update for user's own flashcards"
ON public.flashcards
FOR UPDATE USING (
  auth.uid() = user_id
);

-- 5. Policy for DELETE
-- Users can delete their own flashcards.
CREATE POLICY "Enable delete for user's own flashcards"
ON public.flashcards
FOR DELETE USING (
  auth.uid() = user_id
);
```

### Generations Policies:

```sql
-- 1. Enable RLS on the table
ALTER TABLE public.generations ENABLE ROW LEVEL SECURITY;

-- 2. Policy for SELECT
-- Users can read their own generation logs (e.g., for future stats).
CREATE POLICY "Enable read access for user's own generation logs"
ON public.generations
FOR SELECT USING (
  auth.uid() = user_id
);

-- 3. Policy for INSERT
-- Users can create new generation logs for themselves.
CREATE POLICY "Enable insert for own generation logs"
ON public.generations
FOR INSERT WITH CHECK (
  auth.uid() = user_id
);

-- 4. Policy for UPDATE
-- (No UPDATE policy needed - logs should be immutable)

-- 5. Policy for DELETE
-- (No DELETE policy needed - logs should be immutable, only deleted via ON DELETE CASCADE)
```

## 5. Additional Notes & Functions

### updated_at Trigger:

A trigger function is needed to automatically update the updated_at timestamp on the flashcards table whenever a row is modified (US-015).

```sql
-- 1. Create the function
CREATE OR REPLACE FUNCTION public.handle_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 2. Create the trigger
CREATE TRIGGER on_flashcards_updated
BEFORE UPDATE ON public.flashcards
FOR EACH ROW
EXECUTE FUNCTION public.handle_updated_at();
```
